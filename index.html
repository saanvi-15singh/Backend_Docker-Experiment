🎯 1. Project Title & Overview

Project Title: Student Management API using FastAPI and Docker

The objective of this experiment is to develop a reliable backend application using FastAPI and deploy it using Docker. The project implements a Student Management API allowing full CRUD operations (Create, Read, Update, Delete) on student records.

The application is containerized using Docker so that it runs in an isolated, reproducible container environment regardless of local machine configuration. In addition, Docker Compose simplifies building, starting, and stopping the containerized service.

  5. Create an optimized Dockerfile based on Python 3.13 slim.
  6. Build and run Docker container images locally.
  7. Configure docker-compose.yml for simplified container lifecycle management.

Step 3: Developing FastAPI Application (main.py)

The backend application defines data schemas with Pydantic and creates clean route handlers:

from fastapi import FastAPI, HTTPException
from pydantic import BaseModel

app = FastAPI(title="Student Management API")

# In-memory student records
students = [
    {"id": 1, "name": "Saanvi", "course": "CSE"},
    {"id": 2, "name": "Sakshi", "course": "CSE"}
]

class Student(BaseModel):
    name: str
    course: str

@app.get("/")
def home():
    return {"message": "Welcome to Student Management API"}

@app.get("/health")
def health():
    return {"status": "Application is running"}

@app.get("/students")
def get_students():
    return students

@app.get("/students/{student_id}")
def get_student(student_id: int):
    for student in students:
        if student["id"] == student_id:
            return student
    raise HTTPException(status_code=404, detail="Student not found")

@app.post("/students")
def add_student(student: Student):
    new_student = {
        "id": max([s["id"] for s in students], default=0) + 1,
        "name": student.name,
        "course": student.course
    }
    students.append(new_student)
    return new_student

@app.put("/students/{student_id}")
def update_student(student_id: int, updated: Student):
    for student in students:
        if student["id"] == student_id:
            student["name"] = updated.name
            student["course"] = updated.course
            return student
    raise HTTPException(status_code=404, detail="Student not found")

@app.delete("/students/{student_id}")
def delete_student(student_id: int):
    for student in students:
        if student["id"] == student_id:
            students.remove(student)
            return {"message": "Student deleted successfully"}
    raise HTTPException(status_code=404, detail="Student not found")

Run locally using:

uvicorn main:app --reload

Step 5: Dockerfile Creation

A multi-step Dockerfile packages the FastAPI application into a lightweight container image:

FROM python:3.13-slim

WORKDIR /app

COPY requirements.txt .

RUN pip install --no-cache-dir -r requirements.txt

COPY . .

EXPOSE 8000

CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]

Step 6: Building the Docker Image

Build the container image with tag v1:

docker build -t student-api:v1 .

Step 7: Running the Docker Container

Start the container in detached mode with host port forwarding:

docker run -d --name student-api-container -p 8000:8000 student-api:v1

Check container status:

docker ps

Step 8: Managing Services with Docker Compose

The docker-compose.yml file orchestrates the service:

services:
  student-api:
    build: .
    ports:
      - "8000:8000"
    restart: unless-stopped

Build and start with Compose:

docker compose up -d --build

💡 8. Problems Faced & Solutions

Problem 1: Virtual Environment Path Error

Cause: The virtual environment folder was moved into the project folder from its parent directory. As a consequence, its internal absolute scripts continued referring to the obsolete path, causing pip to crash.

Solution: The corrupted venv directory was removed and cleanly recreated using py -3.13 -m venv venv directly within the project directory.

Problem 2: Incorrect Directory Navigation

Cause: PowerShell terminal was already located in Backend_Docker-Experiment, but attempting to cd Backend_Docker-Experiment again triggered a directory-not-found error.

Solution: Verified the prompt path before issuing navigational commands and executed commands from the current working directory.

Problem 3: Virtual Environment Activation Script

Cause: Executing general activation commands failed on Windows PowerShell due to specific script path requirements.

Solution: Explicitly invoked PowerShell's script: .\venv\Scripts\Activate.ps1.

Problem 4: Differentiating API JSON vs. Terminal Output

Cause: Initial confusion between the raw JSON payload in web browsers and the server log stdout in VS Code terminals.

Solution: Dedicated Terminal 1 for running the ASGI Uvicorn server / Docker containers, and Terminal 2 for executing automated test scripts and inspection commands.

Problem 5: Understanding Docker Images vs. Containers

Cause: Distinguishing the concept of an immutable Docker Image from a live, executing Container instance.

Solution: Practiced building with docker build (creating the blueprint) and instantiating with docker run (creating the active runtime).

Problem 6: Port Conflict on Host Port 8000

Cause: A standalone container was already occupying port 8000 when attempting to launch docker compose up, causing a bind port collision.

Solution: Stopped and removed the active container using docker stop student-api-container && docker rm student-api-container before starting Docker Compose.
